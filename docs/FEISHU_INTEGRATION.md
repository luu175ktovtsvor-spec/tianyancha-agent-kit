# 飞书对接：把获客线索导入飞书

## 两种对接方式

本仓库输出 JSONL、CSV、XLSX 三种格式。可以人工导入飞书表格，也可以在任务工作区写一个适配器，将稳定字段写入飞书表格或多维表格。

如需命令行对接，直接使用飞书官方开源项目 [`lark-cli`](https://github.com/larksuite/cli)。安装、授权和命令以该项目主页为准。

如果还没安装，可以直接让 Agent 按该主页安装并验证 `lark-cli`。

表格字段、同步规则和运行配置由任务工作区管理。

交付链路是：任务 profile 与输入数据 → 本项目输出 CSV / XLSX / JSONL → 人工导入，或由任务适配器写入飞书表格或多维表格。

## 推荐的表结构

| 表 | 一行代表什么 | 建议主键 | 关键字段 |
| --- | --- | --- | --- |
| 电话主表 | 一个主体 | `credit_code` | `name`、`entity_class`、`phone_count`、`phone_1...n`、`city`、`district` |
| 电话明细 | 一个主体—电话组合 | `credit_code + phone` | `credit_code`、`name`、`phone`、`phone_index`、分类与位置 |
| 淘汰审计 | 一条未入选候选 | 来源 ID 或审计 ID | `reason`、必要的复核字段 |

其中 `credit_code` 是首选主体去重键；如果数据源不提供它，可在任务适配器中使用 `source_id` 和人工复核策略作为兜底。不要用企业名称单独作为自动写入键。

### 方式一：人工导入

1. 在任务工作区执行 `phone-leads`，生成 CSV 或 XLSX。
2. 人工抽查电话、主体类别和淘汰原因。
3. 导入飞书表格或多维表格，按 `credit_code` 去重。
4. 导入后核对主体数、电话号码数和重复数。

适合一次性或低频交付。

### 方式二：任务适配器

在任务工作区实现同步器：

1. 读取本项目输出的稳定字段；
2. 以 `credit_code` 对电话主表做新增/更新；
3. 以 `credit_code + phone` 对电话明细做去重；
4. 写入批次时间、来源和复核状态；
5. 回读飞书并与本地输出核对主体数、电话数和异常项。

适配器直接读取本项目的稳定输出字段，并按团队自己的表格结构同步。

## 导入前后的最低复核标准

- 进入电话表的主体必须至少有一个来源实际返回的电话；不得补造号码。
- 主表主体数应等于去重后的电话主体数；电话明细数应等于主体—电话号码的唯一组合数。
- 同一主体多个电话应保留为多列或多行，不能只保留第一个号码。
- 对接完成后回读飞书，检查缺失、重复、错位和异常公式。
