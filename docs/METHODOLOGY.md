# 筛选方法论：从企业数据到可复核获客线索

本项目可以通过 Playwright 可见浏览器读取任务页面结果，也可以处理已有 JSON 文件。Agent 打开浏览器后，任务负责人在浏览器里扫码登录；确认结果页可用后，Agent 再读取页面结果。

行业条件由任务负责人决定，不是公开仓库预设的标准。将行业、保留和排除条件、主体、风险、日期、地区、电话和飞书字段要求交给 Agent 后，Agent 应在任务工作区调整配置；公开示例只说明写法。

## 固定处理顺序

1. 统一字段，并按 `credit_code` 或 `source_id` 稳定去重。
2. 判断正向词、负向词与必含词。
3. 判断主体类型、成立日期、经营状态与风险阈值。
4. `phone-leads` 要求至少一个电话，再检查地区范围。
5. 按 `entity_classes` 分类；进入目标分类的记录生成电话总表和主体分表，其余记录保留淘汰原因。

前一关失败即保留第一个淘汰原因，后续规则不再覆盖该原因。

| 阶段 | profile 字段 | 判断对象 | 结果 |
| --- | --- | --- | --- |
| 去重 | `credit_code`、`source_id` | 同一主体候选 | 优先保留最先出现的记录 |
| 正向词 | `positive_terms` | 名称、经营范围、类别 | 设置后至少命中一个 |
| 负向词 | `negative_terms` | 名称、经营范围、类别 | 任一命中即淘汰 |
| 必含词 | `required_terms` | 名称、经营范围、类别 | 设置后必须全部命中 |
| 主体 | `entity_mode` | 主体类型文本 | 可限定个体、企业或全部 |
| 质量 | 日期、状态、风险阈值 | 标准化字段 | 逐项比较，不满足即淘汰 |
| 电话 | `phone_leads.min_phone_count` | 去重后的电话列表 | `phone-leads` 最低为一个电话 |
| 地域 | `allowed_cities`、`allowed_districts` | 城市、辖区 | 电话准入后核验明确配置的范围 |
| 分流 | `entity_classes`、`target_entity_classes` | 主体类型文本 | 有序首次匹配；未选中的类进入淘汰审计 |

## 复核原则

1. 每个入选主体至少应存在一个输入来源实际返回的电话。
2. 多个电话应完整保留，不得因为导出结构只保留第一个号码。
3. 规则变更应在处理前写入 profile，并以小样本检查入选与淘汰原因。
4. 对外使用前应根据任务要求检查地址、负责人、电话等字段是否需要脱敏。
